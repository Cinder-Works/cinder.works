The Four-Clause Unit Test

The spine of every playbook. Not negotiable.

  • The agent never speaks as the owner without per-message approval. Voice modeling is fine. Voice impersonation is not.
  • The agent never makes a call the owner can't undo. Sends, spends, signs, posts — all queue.
  • Money always = approval. Even small amounts. No "the agent has a $20 budget."
  • The agent never approves its own permission escalations.

These four are the answer to the 2 a.m. fear. They're not philosophy — they're the unit test every agent decision passes before it acts, and they show up in every playbook in the kit. The free packs teach your agent to act. This is the part that decides when it shouldn't.

Same four clauses, now governing more machine. The spine held.

Honest Caveats

This is not for everyone. The honest list.

If you have employees, you want a different kit.
The role-separation patterns we use assume one operator + one agent. AMP (Rachel Woods's work) is shaped for teams. We're explicitly below that floor.
If you won't iterate on prompts, the agent will underperform.
The playbooks are calibrated through real-world overrides. The first month is mostly correcting the agent. That's expected. If "set and forget" is what you want, this isn't it.
If you do 200 low-margin transactions a day, the per-action token cost matters.
The kit's pattern works best for lower-volume, higher-margin shops where each transaction is worth the agent's attention. High-volume e-commerce wants different tooling.
If you're in highly regulated work, the queue-for-approval pattern may not scale.
Medical, financial advice, legal — anything that needs human review per action — the time-to-decision math gets tight. Worth a conversation before adopting.
